# 规划模板设计：四件套与「无证据不进设计」

> 状态：草案（WS-007 规划已确认，交付待人 sign-off）· 日期：2026-10-03 · 关联：`.dsh/requirements/REQ-004.md`、`.dsh/workstreams/WS-007.md`、`.dsh/workstreams/WS-008.md`、`docs/design/panels/requirements-workstream-store-design.md`、`docs/research/ai-native-workflow-architecture.md`、`.dsh/ai-native-workflow-spec.md`

## 1. 目的与范围

把事项「规划」阶段的完成物定形为**可照抄的标准模板**（四件套），给出每项的定义 / 必填性 / 判据 / 正例，
并定义「无证据不进设计」门禁的**判据接口**。

**本设计做**：定形四件套、给模板骨架、给门禁判据接口、说明与既有权威的关系。

**本设计不做**（范围外，按 R5 另起卡片）：

- 不实现可执行 checker / 回归门（属 WS-008 / `REG-002`）；
- 不建面板 / 拆解器；
- 不改 `.dsh` 既有卡片正文、不改任何代码；
- 不改 `.dsh/ai-native-workflow-spec.md`（项目无关规范，另起）；
- 不动验收 / 交付 / 裁决 / 覆盖 / 终态规则。

## 2. 四件套

规划阶段的**完成物 = 四件套**；缺任一，规划未完成 → 不进设计（架构 §4.2）。

| # | 件 | 回答的问题 | 必填性 |
|---|---|---|---|
| P1 | WHAT（目标） | 这次要达成什么？ | 必填，1 条 |
| P2 | 边界 | 做什么 / 不做什么？ | 必填，「做」与「不做」各 ≥1 条 |
| P3 | 验收标准 | 怎么算完（可机检）？ | 必填，≥1 条编号 AC |
| P4 | 阶段裁剪声明 | 跳过哪些后续阶段、为何 / 如何承载？ | 必填（显式，哪怕「不裁剪」） |

### P1 WHAT（目标）

- **定义**：一句话说清本事项要向世界交付的**可观察结果**，不是活动清单。
- **必填性**：必填，1 条。
- **判据**：`## 规划` 内存在「目标」条目且非空。是否「可观察」由人 Review。
- **正例**：`目标（WHAT）：产出 docs/design/panels/planning-template-design.md，把规划四件套定形为可照抄模板。`

### P2 边界

- **定义**：**做**（本事项包含的改动面）与**不做**（明确排除、会顺带发生但不就地吸收的工作）两栏。
- **必填性**：必填，两栏各 ≥1 条。
- **判据**：`## 规划` 内含「边界（做）」与「边界（不做）」两栏且各非空。
- **正例**：见 §3 骨架。

### P3 验收标准

- **定义**：可机检的通过判据清单，编号 `AC1..ACn`；每条给出**可观察**的通过条件（命令 / 文件 / 值）。
- **必填性**：必填，≥1 条。
- **判据**：`## 规划` 内含「验收标准」，且至少 1 条形如 `AC<n>`。
  「可机检」的**质量**由人 Review——门禁只查存在与编号，不假装判定质量。
- **正例**：`AC6 回归门 REG-001 通过（node .dsh/regression/check-architecture-model.mjs）。`

### P4 阶段裁剪声明

- **定义**：显式声明本事项**跳过哪些后续阶段**（规划 / 设计 / 任务 / 验收 / 交付）及其承载方式；
  不裁剪也必须写「不裁剪」（R3：裁剪决策本身是规划产物）。
- **必填性**：必填。
- **判据**：`## 规划` 内含「阶段裁剪声明」条目且非空。
- **正例**：`阶段裁剪声明：裁剪「设计」与「设计评审」（产物即模板本身，评审以 PR review 承载）；不裁剪规划 / 验收 / 交付。`

## 3. 模板骨架（可直接照抄）

```md
## 规划

- 目标（WHAT）：<可观察结果>
- 边界（做）：
  - <本事项包含的改动面>
- 边界（不做）：
  - <明确排除 / 回池的工作>
- 阶段裁剪声明：<跳过哪些阶段 + 承载方式；不裁剪则写「不裁剪」>
- 验收标准（规划完成证据）：
  - AC1 <可观察的通过条件>
  - AC2 <可观察的通过条件>

## 规划确认（人）

- <日期> 人确认本卡「规划」（目标 / 边界 / 阶段裁剪声明 / AC）。
```

## 4. 门禁判据接口（「无证据不进设计」）

- **适用对象**：`stage ∈ {design, task, acceptance, delivery}` 的事项卡。
- **证据**：P3 验收标准 + P4 阶段裁剪声明（架构 §4.2：完成证据 = 验收标准 + 被裁剪阶段的声明）；
  P1 / P2 同列，用于模板完整性。
- **判定**：四件套齐 → PASS；缺任一 → FAIL，并指明卡 + 缺失项。
- **`stage=planning` 不检查**（尚未进设计）。
- **实现**：由 WS-008 落地为 `.dsh/regression/REG-002.md` + checker；本设计只定判据接口，不含脚本。
- **自证**（架构原则 9）：门禁须能用缺证据的样例失败，否则「绿」不算数。
