
# UI 交互走查与设计评审：工程脚手架

> 文档性质：**UI/交互分析与评审** —— 从「管理（环节 / 项目预设）」到「日常使用（新建 / 初始化 / 更新 / 当前项目首页）」对现有交互做逐项走查，并**如实指出交互设计的优点与缺点**。
> 来源基线：platforms/macos/src/ScaffoldPanel.swift（面板 UI/控制器，分支 feature/scaffold-workbench）+ main.swift 集成。
> 定位口径：**企业工程规范落地**（详见 docs/scaffold-panel-analysis.md）。
> 撰写：2026-08。评审判据以当前代码为准；标注「推断 / 待人工 QA」处为从代码推演、需在 App 内确认。
> 配套：功能分析 docs/scaffold-panel-analysis.md · 技术设计稿 docs/scaffold-workbench-design.md · 布局活文档 docs/appkit-ui-layout-guide.md。

## 0. 摘要

工程脚手架把「起项目 / 落规范」做成了右侧活动栏里的一个多视图面板，实际承载**两条任务主线**：
- **日常使用**：为项目（新的或当前的）勾环节、填参数、生成 / 重生成工程骨架；
- **管理**：维护「环节库」与「项目预设」（两套一等资源），含用户库覆盖 / 恢复 / 删除 / 排序 / 源码式与结构化编辑器。

两条主线由顶层入口层收敛：常态展示「当前项目 / 工作区」首页，向导四步（目标与位置 → 选择环节 → 参数配置 → 预览与生成）走日常主线；齿轮设置（环节管理 / 项目预设两个页签）走管理主线，设置是**整面板覆盖**（隐藏时间线与工具栏）。

**核心结论**：
- 优点：进程可视化的时间线、可自由前进到预览再统一收敛校验、预设一键套用但可再改选、参数控件随类型自适应、管理资源有「内置 / 已修改 / 新建」标记与可恢复防呆、生成后台化非阻塞、落盘后自动关联 dsh 工作区。
- 缺点：管理入口深且隐蔽（齿轮覆盖整个面板、预设还要再切页签）；环节管理本质是 **YAML / 模板的代码编辑**，与日常向导体验断层；「项目简介」在步骤 1 必填标红但只在选了 agents-md 时真正强制，存在两处同语义字段的双向联动与锁定（techSummaryLocked），心智成本高；步骤 1–3 的「下一步」始终可点、直到预览才统一拦截错误，反馈滞后；无生成前内容抽查 / diff，只能落盘后再看。

## 1. 评审范围与对象

面板提供三条「生成入口」（工具栏按钮）+ 一个常态首页 + 一个管理覆盖层：

| 对象 | 归属主线 | 说明 |
|---|---|---|
| 当前项目 / 工作区 首页（第 1 轨） | 常态 | 解析 dsh 活动工作区；已初始化项目显示环节/参数卡片 + 打开 / 显示 |
| 新建项目 向导 | 日常 | 目标与位置 → 选择环节 → 参数配置 → 预览与生成 |
| 初始化此目录 / 更新配置 | 日常 | 复用向导的快捷入口（前者空目录、后者读 state.json 重生成） |
| 环节管理（设置·页签 1） | 管理 | 环节列表 + 源码编辑器（stage.yaml + 模板多文件） |
| 项目预设管理（设置·页签 2） | 管理 | 预设列表 + 结构化编辑器 |

评审把「日常使用」与「管理」各走一遍，再讲跨主线的信息架构与状态流转。

## 2. 面板信息架构与导航（三层）

面板从上到下大致为：顶部**头部**（标题 + 右上角齿轮）→ 顶部**工具栏**（[新项目][初始化此目录][更新配置]）→ **时间线轨**（当前项目 / 目标与位置 / 选择环节 / 参数配置 / 预览与生成 5 项）→ 步骤内容区（滚动）→ 底部**上一步 / 下一步（或 生成）** 与**状态条**。

管理覆盖层（设置）把工具栏、时间线、步骤视图全部隐藏，替换为：头部（< 返回 + 标题 + 新建按钮）→ 页签切换（环节管理 / 项目预设）→ 可滚动列表（行含徽标与 编辑 / 恢复 / 删除 / 上移 / 下移）→ footer（用户库路径）。列表行再下钻一层到**编辑器**（多文件页签或结构化表单）。

层级示意：

    （常态）首页  <->  向导（步骤1..4）               ← 日常使用
        └── 齿轮 → 设置（环节管理 | 项目预设）         ← 管理（整面板覆盖，隐藏上面全部）
                     └── 环节编辑器（多文件 YAML+模板）/ 预设编辑器（结构化）

三层导航各有返回语义：向导内「上一步」；管理用「返回」；从向导任意步 Back 到首页即取消（复位）。

## 3. 交互对象速查

| 对象 | 外观 / 行为 |
|---|---|
| 时间线轨（ScaffoldStepItem） | 数字徽标圆点 + 标题；状态 idle / current / done / error，点按即跳转步骤 |
| 环节卡片（ScaffoldStageCard） | 整卡点按切换勾选；圆角描边，选中高亮 + 勾选徽标；名称 + 两行描述 |
| 参数控件 | string→文本框；select（少于 5 项）→radio 组、否则下拉；bool→勾选框；multiselect→纵向多选；必填标签标红 + 空值红框 |
| 预览（rebuildPreview + 文件树） | 消息区（校验错 / 渲染错 / 提示）+ 文件树；冲突文件标橙并列出覆盖来源 |
| 底部按钮 | 步骤 1–3 为「上一步 / 下一步」；步骤 4 变「生成」（门控）；生成中 spinner + 状态条 |
| 设置列表行 | 名称 + 类型徽标（内置 / 已修改 / 新建）+ 描述 + [编辑][恢复][删除][上移][下移] |
| 环节编辑器 | 头部（<返回 + 标题 + 保存）+ 多文件页签（脏标记 + 新建模板）+ 编辑区 |
| 预设编辑器 | 头部 + 字段（名称中英 / 描述中英）+ 环节多选 + 每环节参数默认值（控件）+ 保存 / 返回 |

## 4. 日常使用主线：新建项目向导（步骤 1→4）

### 4.1 步骤 1 目标与位置
- 交互：项目名文本框、项目简介文本框（标 * 红）、父目录选择（NSOpenPanel，sheet 弹出，记忆上次目录；选中目录即把父目录与目录名预填）、「按目的预设」按钮行（读取内置 + 用户预设）。
- 就绪度：时间线仅当 name + parentDir 非空才把该步标 ✓；但「下一步」在此步**始终可点**（门控只在步骤 4）。
- 可观察点：目标根（将创建目录）随项目名 / 父目录实时变化；项目简介同步进 agents-md 的 techSummary（若未被步骤 3 独立改过则自动覆盖）。

### 4.2 步骤 2 选择环节
- 交互：环节卡片列表（按 category 分组、按排序）；点卡片入组、再点移出；顶部显示「已选 N 个」；预设在此刻被展开为该环节组的勾选与参数默认值。
- 就绪度：选中 ≥1 即标 ✓。
- 可观察点：勾选即触发 refreshPlan（实时重算文件清单 / 冲突 / 校验），为预览预热。

### 4.3 步骤 3 参数配置
- 交互：按选中环节逐环节列出参数表单（StageEditor 扁平行，控件随 type）。进入本步会**强制重建表单**（避免隐藏期布局塌陷）。
- 可观察点：必填参数（带校验器）标签红色 + 空值红框，由 updateRequiredHighlights 实时维护；但**不阻止前进**，只影响步骤 4 的生成门控。
- agents-md 的 techSummary 在此可被直接编辑，编辑后 techSummaryLocked=true，步骤 1 的简介不再回写。

### 4.4 步骤 4 预览与生成
- 交互：消息区（错误 / 提示）+ 文件树（自动展开根目录）+ 冲突标记；底部按钮变「生成」。
- 门控：生成仅在 name + parentDir 非空 && plan.isValid && 非生成中 时可用（步骤 1–3 的下一步不受门控）。
- 生成动作：非空目标目录弹确认（覆盖 + 备份）→ 后台执行 → 状态条 完成 / 失败 → 成功后 best-effort 登记 dsh 工作区。
- 完成后无明确的「查看结果」出口，返回首页经工作区卡片打开 / 显示。

### 4.5 交互节奏小结
「先自由推进 → 最后统一收敛校验」是有取舍的选择：链路顺滑、不打断，但**错误暴露滞后**（见 §9.4）。

## 5. 日常使用主线：初始化此目录 / 更新配置 / 当前项目首页

### 5.1 初始化此目录
- 入口常显，但仅当前工作区为**空目录**时可用（否则禁用）。点击从「选择环节」步直接进入（目标已锁定为当前目录，不改名）。
- 语义：把规范生成到既有（空）目录内——适合「目录已建、想套规范」或「克隆了空目录后补齐工程规范」。

### 5.2 更新配置（重生成）
- 入口仅在当前目录含 .scaffold/state.json 时可用。点击读回 state.json 的环节 / 参数 → 载入向导（停在步骤 1 确认目录 / 项目名 → 下一步即带出已载入内容）→ 改选 / 改参 → 生成（幂等覆盖 + 备份）。
- 语义：对**已生成的既有项目**做「微调规范再落一次」——这是把脚手架用于存量项目治理的关键能力，也是「企业规范落地后可持续维护」的支点。

### 5.3 当前项目 / 工作区 首页
- 解析 dsh 活动工作区路径；若该目录带 state.json → 显示「已由脚手架初始化 ✓」+ 文件数 + 每环节配置卡片（环节名 + 非空参数行）+ [打开目录][在 Finder 中显示]；未初始化则给提示并按目录是否为空启用 / 禁用「初始化此目录」。
- 真正切换工作区（目录变了）→ 自动回首页、清空向导；仅会话变（同目录）→ 只刷新工具态。
- 首页本身无前进按钮（下一步禁用），进入向导的唯一方式是通过工具栏或预设。

## 6. 管理主线：环节管理 与 项目预设管理

### 6.1 环节管理（设置 · 页签 1）
- 列表：全量环节（内置 + 用户自定义 / 已修改），类型徽标区分；每行 编辑 / 恢复 / 删除 / 上移 / 下移。恢复（删用户拷贝回内置）与删除（仅自定义）都有确认弹窗；排序持久化。
- 编辑器：多文件页签（stage.yaml + templates/ 每个文件一个），CodeEditorView 行号 / 高亮 / 撤销，脏标记「文件名 + *」，可「新建模板」。「保存」先确保 stage.yaml 已存（先定环节 id）再存模板；改内置保存即物化到用户库（可恢复）；footer 显示用户库路径。
- 保存语义与文件面板一致：逐文件保存、保存后留在编辑器。

### 6.2 项目预设管理（设置 · 页签 2）
- 列表：内置种子（backend / fullstack / foundation）+ 用户覆盖，徽标；编辑 / 恢复 / 删除 / 排序。
- 编辑器是**结构化表单**（非 YAML）：名称（中 / 英）+ 描述（中 / 英）+ 环节多选卡片（按勾选序入组）+ 每环节参数默认值（复用各类型控件）。新建按名称 slug 生成 id，编辑不改 id。
- 向导步骤 1 的预设行读同一库，缺环节标注「（缺失环节 …）」；套用时仅勾选当前库仍存在的环节。

### 6.3 管理体验小结
管理把「环节」当**可编程资源**（YAML + 模板源码），把「预设」当**可配置资源**（结构化表单）。对开发者友好的同时，把「普通用户想复制 / 微调一个环节」拦在源码门槛后。

## 7. 跨主线一致性与状态流转

| 维度 | 表现 | 评价 |
|---|---|---|
| 双主线共用入口 | 首页常态 + 齿轮进管理 | 收敛，但管理是整面板覆盖，情境被替换 |
| 时间线徽标 | 步骤就绪度即画 | 优秀：进程可视化 + 可跳转 |
| 就绪态只到「生成」门控 | 步骤 1–3 不阻塞 | 顺滑但反馈滞后 |
| 返回语义 | 向导 Back 到首页即取消并复位 | 明确但复位无确认，易误失已填 |
| 状态回写 | 步骤 1 简介 ↔ agents-md techSummary 联动 + 锁定 | 便利但双字段 + 锁定心智成本高 |
| 落盘与工作区 | 生成后幂等登记 dsh 工作区 | 优秀的桥接，打通「起项目 → 开发」 |
| 深浅色 / 语言 | 控件按 effectiveAppearance 显式取色、外观变化即刷新；L10n 双语 | 与既有面板一致 |

## 8. 交互设计优点（逐条）

### 8.1 时间线 = 进程可视化 + 可逆导航
五步时间线以 数字 / ✓ / ! 徽标实时反映各步就绪度，且点任意步骤可直接跳转；「上一步」逐级回退，Back 到首页 = 取消。把「多步配置」的进度与出口画在明面上，用户在长配置流程里永远知道自己在哪、能去哪。

### 8.2 「先自由推进、最后统一校验」降低打断感
步骤 1–3 不因个别参数卡死，让用户把该选选完、该填填完，在预览集中看错误 / 提示与文件树。对「试探性组合」友好（企业用户常边选边看效果）。

### 8.3 预设「一键套用但可再改选」，不锁死组合
预设只是快捷勾选 + 注入参数默认值，之后仍可增删环节、改参数。既快又有自由度，不会把用户绑死在模板语义里。

### 8.4 实时预览 + 冲突前置暴露
勾选 / 填参即 refreshPlan，预览区实时给文件树与冲突（后写覆盖 + 来源链标橙）。冲突在**落盘前**可见、可经调序 / 取消解决，符合「先看清楚再动手」的安全感。

### 8.5 参数控件随类型自适应 + 内联必填反馈
string / select（radio 或下拉）/ bool / multiselect 各有最贴合的控件；必填参数红 * + 空值红框，采用「值实时判定」（不误判默认值）。

### 8.6 管理资源防呆
环节 / 预设都有「内置 / 已修改 / 新建」徽标，恢复（删用户拷贝回内置）与删除（仅自定义）分得很清且有确认；改内置保存即物化、可一键恢复——不怕改坏。

### 8.7 生成的非阻塞与后台化
生成在后台队列执行、spinner + 状态条反馈，不卡 UI；git init 失败不阻断、明确提示。

### 8.8 落盘与 dsh 工作区桥接
生成成功后 best-effort 把新项目登记为 dsh 工作区（幂等、顺带建空 session）——「起项目 → 直接进开发」一步到位，是「企业规范落地后立即能开工」的强连接。

## 9. 交互设计缺点与改进建议（逐条）

### 9.1 管理入口深且隐蔽，双主线断层【高】
**现象**：管理（环节 / 预设）藏在右上角齿轮，点开是**整面板覆盖**（时间线与工具栏全隐藏），要再切页签才到预设；从「日常用向导」到「管理环节」是两个几乎不相连的深路径，新手不易发现这里还能自己加环节 / 预设。
**建议**：A) 首页 / 向导给「管理环节库」的显式文字入口（而非只有齿轮图标）；B) 设置以抽屉 / 次级页而非整面板覆盖呈现，保留面包屑与当前向导上下文；C) 预设管理更贴近向导（步骤 1 预设区提供「编辑此预设」就地入口）。

### 9.2 环节管理 = 源码编辑器，门槛断层【高】
**现象**：改一个环节要面对 YAML + 模板多文件源码页签；对只想「复制环节改个参数 / 加个文件」的普通 / 团队使用者是硬门槛，而企业场景恰常由非 Swift 开发者维护规范。
**建议**：为环节提供「参数 / 文件 / 命令」的**结构化编辑**（仿预设编辑器），YAML 仅作进阶入口保留；或至少对 stage.yaml 做字段表单化 + 模板文件仍源码。

### 9.3 必填「项目简介」语义不一致 + 双字段联动锁定【中-高】
**现象**：步骤 1 的项目简介恒标红 *，但真正强制只在选了 agents-md 环节时（其 techSummary 校验）；且同一内容在步骤 1 与步骤 3 两处出现，靠 techSummaryLocked 决定谁回写谁——用户不易理解为何「在步骤 3 改过一次后，步骤 1 就不理我了」。
**建议**：A) * 仅在选中 agents-md（或对应参数必需）时显示，否则降为可选提示；B) 把「项目简介」从步骤 1 的必填项改为「预填 agents-md 的 techSummary」的辅助字段，并明示联动关系；C) 避免双字段双写——只在步骤 1 维护简介，步骤 3 展示为只读继承或提供明确的「覆盖」开关。

### 9.4 校验反馈滞后到步骤 4【中】
**现象**：步骤 1–3 的「下一步」始终可点，错误（如非法包名、路径穿越）直到预览才以错误提示出现；用户可能一路点到最后才发现要回头改。
**建议**：时间线徽标已能标 error；在此基础上于「下一步」附近给出轻量前瞻提示（或允许点到但高亮待改项并可直接跳转），不必强制阻断。

### 9.5 无生成前「内容抽查 / diff」【中】
**现象**：预览只有文件清单树，看不到任一模板的**最终渲染内容**，也无与既有文件的 diff；对「想确认生成出来长什么样」再落盘的用户，只能先落到临时目录再验证。
**建议**：A) 文件树上点某文件弹出最终渲染内容预览；B) 「更新配置 / 重生成」场景提供 .scaffold-backup/ 的旧新 diff 入口。

### 9.6 冲突仅提示、无快速消解【中】
**现象**：预览只把同路径多环节写标红列来源，用户需手动排查是哪个环节、再回步骤 2 取舍；没有「一键跳过冲突环节」或冲突侧提示可点跳到来源环节。
**建议**：冲突行提供「跳到来源环节」动作与「从该环节移除冲突文件」选项（文件可被条件 / 开关屏蔽）。

### 9.7 Back 到首页 = 取消，无确认易失已填【低-中】
**现象**：从向导任意步点「上一步」直到回到首页即判定为取消并**复位全部已填 / 已勾**，无二次确认。长配置被误触回退会白干。
**建议**：仅在确有未完成变更时弹「放弃本次向导？」；或提供向导草稿记忆。

### 9.8 首页无主 CTA，入口依赖发现【低-中】
**现象**：首页本身无前进按钮，从「当前项目」到「起一个新项目」需先意识到顶部工具栏的「新项目」。首次用户可能停在首页不知从何开始。
**建议**：首页提供显著主按钮「新建项目」（或空态引导），让「从这里开始搭规范」一目了然。

### 9.9 实现层面：嵌套表单布局脆弱【中，工程】
**现象**：代码中多次处理「隐藏期嵌套 stack 塌陷 → 进入时强制重建」「滚动步骤置顶时间窗」「按 fittingSize 钉死行宽」等，暗示参数 / 设置区布局在运行时易塌陷 / 跳动；设计稿亦注明「表单运行时布局需人工 QA」。
**建议**：按 docs/appkit-ui-layout-guide.md 做一次 App 内人工 QA，优先把「参数多环节 + 长模板文件」场景的滚动高度与重建闪动修稳；沉淀到布局活文档。

### 9.10 入口图标与命名偏工具化【低】
**现象**：活动栏 puzzlepiece.extension 图标 + 「脚手架」文案，对「为企业项目落规范」的价值主张表达不够直观。
**建议**：可评估更贴合「工程规范 / 项目生成」语义的图标与副标题，属定位表达优化。
