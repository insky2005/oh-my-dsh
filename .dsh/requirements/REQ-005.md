## 诉求

裁决锚点不能用可变指针（git ref）。两个实例：

- **F7 抗 rebase**：记录裸 commit 哈希，分支被 rebase / amend 后失效。已实际发生：
  WS-001 的 `78249c6` 在 11:08 被 rebase 成 `29e6a46`。
- **F8 抗记录动作**：锚定「分支 tip」，则记录验收这个动作本身推进分支、令裁决当场作废
  （自失效）。原则 8 旧表述「该分支再有新提交即失效」有此问题。

## 方案（内容寻址）

裁决只记两样：

```yaml
anchor_paths:  [被裁定产物路径清单]
anchor_digest: 该清单的内容聚合摘要
```

摘要算法（工作树可直接算，不依赖提交）：

```sh
for f in <paths>; do printf '%s  %s\n' "$(git hash-object "$f")" "$f"; done | sort | git hash-object --stdin
```

- 复核：当前摘要 == `anchor_digest` → 裁决有效；否则失效。
- 文件再多也是**一个** digest；不新增 blob（git 本就存了每个文件版本）。

## 边界

- 锚点覆盖被裁定**产物**，不含裁决卡自身（否则自指，等同 F8）。
- 粒度到**文件级**：同一文件被两个事项先后修改会互相令裁决失效（Q13）。
