## 诉求

裁决锚点不能用可变指针（git ref）。两个实例：

- **F7 抗 rebase**：记录裸 commit 哈希，分支被 rebase / amend 后失效。已实际发生：
  WS-001 的 `78249c6` 在 11:08 被 rebase 成 `29e6a46`。
- **F8 抗记录动作**：锚定「分支 tip」，则记录验收这个动作本身推进分支、令裁决当场作废。

## 纠偏：裁决是点记录，不是实时谓词

第一版方案（「内容一变即失效」）是**错的**：它把裁决当成了对当前内容求值的谓词。
正确模型：

1. **点记录**：裁决 = 判定人 + 证据 + **覆盖的那次变更**（不可变 blob/tree）。判定后**永不失效**。
2. **覆盖**：后续改动只是**未被该裁决覆盖**；验证义务跟随**引入改动的事项**，不跟随文件。
3. **回归门**：长期不变量从「点记录」升级为每次改动都跑的检查（REG-001）；
   后事项打破它 → **后事项失败**，不是前事项重开。
4. **终态**：事项关闭（已交付 / 已放弃 / 被取代）后不再回边、不再重验；重开另起事项并回指。

## 覆盖字段

```yaml
covered:
  paths: [被裁定的路径]
  base: 变更前的内容标识（不可变）
  head: 变更后的内容标识（不可变）
regression: REG-001
```

摘要算法（不依赖提交，rebase 免疫）：

```sh
for f in <paths>; do printf '%s  %s\n' "$(git show "$rev:$f" | git hash-object --stdin)" "$f"; done | sort | git hash-object --stdin
```

## 边界

- 锚「变更（diff）」，不锚文件整体、不锚分支 / 裸 commit；
- 锚点不含裁决卡自身；
- 跨事项长期成立的部分 → 回归门。
